# Homework 07 — Clickable Prototype and First Feedback

## Project: Exotic Pet Keeper

### Figma Prototype

[Open the clickable prototype](https://www.figma.com/proto/LqJRKvQKSnCPGnXdbsarWf/Exotic-Pet-Keeper-%E2%80%94-Homework-6-Wireframes?node-id=1-2&starting-point-node-id=1%3A2&page-id=0%3A1)

The prototype reuses the Homework 6 wireframes and demonstrates recording a feeding event and retrieving its details.

### Main Flow

Dashboard → Quick Feeding → Completed Example → Feeding Saved → Feeding History → Feeding Record Details.

The prototype also includes a reachable form-validation error state and working back navigation.

### Trial Scenario

You keep exotic animals and use Exotic Pet Keeper to maintain feeding records. You recently fed your leopard gecko, Milo.

**Task:** Use the prototype to record the example feeding for Milo. Then locate the saved record and check its details.

**Starting point:** Dashboard.

**Success criterion:** Reach Feeding Record Details and verify the feeding information.

### Known Limitations

- The prototype uses fictional data.
- Form inputs are not fully interactive.
- Records are not saved to a database.
- Only the first history record has a connected details screen.
- Secondary application functions are outside the tested flow.

### Simulated Feedback Examples

These observations are fictional examples demonstrating the required research format. They are not results from a real student trial.

**Observation 1**

- Quote: "I expected to enter the feeding information myself."
- Observation: The simulated participant tries to interact with the empty form.
- Interpretation: The predefined example could confuse users expecting real input.

**Observation 2**

- Quote: "Now I understand which information is required."
- Observation: The simulated participant encounters validation messages after attempting to save an empty form.
- Interpretation: Inline error messages clarify mandatory fields.

**Observation 3**

- Quote: "I can find the feeding I just recorded."
- Observation: The simulated participant follows View History and opens the saved example.
- Interpretation: The confirmation-to-history transition is understandable.

### Reflection

**Surprising:** Users might expect to enter their own information instead of selecting a predefined example.

**Useful:** The confirmation screen provides a clear path toward the saved record.

**Would change:** Allow real input and animal selection in a higher-fidelity prototype.

### Trial Status

The prototype's main and error paths were manually checked in Figma Present mode.
